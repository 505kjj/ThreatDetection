How protection is applied

A reputation match can confirm phishing or malware. The browser reports whether reputation protection is available in its latest heartbeat.

Financial lookalikes and suspicious activity generate advisories. Machine learning and visual recognition are research features and are disabled in browser protection.

Recent reporting activity

Reporting coverage

Opted-in browser credentials are counted in aggregate while their heartbeat is fresh. An expired heartbeat can indicate a browser that closed, opted out or lost its connection. Device identities are unavailable.

Address signals

Name lookalikes, typosquatting, Unicode and punycode, and misleading subdomains can trigger a local advisory.

Additional context

Visible credential or payment fields, cross-origin form actions and redirects can strengthen an advisory. Visual recognition remains disabled.

        Optional browser reporting

        When enabled in extension settings, the browser sends its reporting credential, event identifier, detection time, signal and action. Heartbeats include reputation availability.

        Monitoring excludes site addresses, visited pages, page content, passwords and form values.

        Retention and access

        Live and synthetic reports are queried separately. The administrator credential is issued by local setup and held in memory for this session. Manage browser reporting and its separate credential in the extension settings.

        Browser protection

        Reputation matching and financial address checks run in the browser. If you enable activity analysis for a site, it uses a separate endpoint for the configured hostname and activity counts. The research models do not process browsing sessions.

        Local protection and setup
